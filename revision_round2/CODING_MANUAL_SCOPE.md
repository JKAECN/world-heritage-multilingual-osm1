# Scope of `Coding_Manual.docx` (Round-2 clarification)

**Status.** `Coding_Manual.docx` is the frozen first-round double-blind validation manual. It is retained **byte-for-byte unchanged** in this repository as an audit record. SHA-256: `c6c75da73721ac908ec828920fc4bc0c2e06daa28b120f6033caf8bb19aac5cd` (43,277 bytes). Because the original `manifest.yaml` does not index this file, its checksum is registered in `manifest_round2_addendum.yaml` under `frozen_artefacts`.

**What it defines.** The manual governs the independent human coding of the 360-record stratified validation sample reported in manuscript Section 2.4.1. It specifies a three-category judgment (`1 = multilingual`, `0 = non-multilingual`, `9 = uncertain`), a seven-category relationship type, and a confidence rating, applied by two coders to identical blind worksheets. Its core question is whether at least two name forms can reasonably be regarded as realizations of different languages, excluding transliteration/romanization, same-language script variants and purely typographic differences.

**What it does not define.** The manual is **not** an operational definition of the outcome variable used in the regression models or in the distance-band profiles. It does not contain, and has never contained, the wording "primary name carries more than one script"; that shorthand appeared only in the earlier README and is withdrawn. The manual predates the four-definition sensitivity framework (`primary`, `corrected`, `notranslit`, `auxiliary`) and does not mention those codings, the base-language collapsing rule, or the grid-level denominator.

**Why the two differ by design.** The programmatic rules describe the structure of database name fields, whereas the human standard applies a stricter linguistic criterion to a small, deliberately stratified sample in order to expose the construct boundary. Manuscript Sections 2.4.1 and 4.5 state this explicitly: the κ values quantify reproducibility of the frozen human coding standard, not program accuracy, and the stratified sample yields no population-level sensitivity, specificity or false-negative rate. The deliberate difference is evidence about the boundary of the measure; it is not an inconsistency between documents.

**Authoritative definition hierarchy.** For any reproduction or reinterpretation of the outcome variable, use, in this order: (1) manuscript Sections 2.3–2.4.1 and Table 2; (2) Appendix B Table B4; (3) Section 1 "Study design in brief" of this repository's README. `Coding_Manual.docx` is to be read only as the audit record of the first-round blind validation procedure.

**Round-2 documentation alignment.** In response to Reviewer 1, Major 3(b), the README has been re-issued with the four authoritative codings, the 60-to-59 / Puebla disclosure, the 572,922 → 568,661 → 552,553 feature-pool reconciliation and the withdrawal of the dated re-extraction claim. This note clarifies the scope of the remaining frozen document, and the manual itself is left unchanged so that the original blind-coding procedure stays independently auditable rather than being silently rewritten after the fact.
